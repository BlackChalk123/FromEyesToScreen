# 随视 · From Eyes to Screen

**正式版第一版（1.0）**：双击 `启动随视正式版.command`，或打开构建后的 `build/随视 1.0.app`。实现官网选片、透明观看、基础头部旋转、井字线和本地恢复；构建、使用及架构见 [正式版说明](docs/正式版第一版.md)。正式版源码在 `Sources/Suishi/` 与 `Sources/RotationCore/`。下文保留旧 Demo 的实验记录，实验功能不属于正式版。

一个 macOS 视频播放器 demo：支持本地视频和 B 站普通投稿视频，摄像头识别头部侧倾，观看画面平滑旋转。随视的控制区保持水平，B 站播放器自身的控件随其画面旋转。

## 打开与体验

构建后的应用位于 `build/随视.app`，双击打开，也可以双击仓库中的 `启动随视.command`。

1. 点击「导入本地视频」（⌘O），或将视频文件拖入观看区。也可点「试播演示」；B 站视频请用「打开 B 站视频」（⌘L）。
2. 点击「开启摄像头」，在系统提示中允许访问。
3. 坐姿自然、看向摄像头，点击「校准水平」（⌘R）。
4. 向左右侧倾头部，视频画面随之旋转。镜像预览和实时角度便于观察检测结果。

没有开启摄像头时，可以在「随视设置 → 手动体验」启用手动角度，拖动滑杆或选择 ±30°。

- 本地视频：空格播放 / 暂停，左右方向键跳转 10 秒；支持进度、音量、全屏。
- 默认最大旋转范围为 ±45°，可在设置中选择 ±15° / ±30° / ±45° / ±60° / ±90°。默认预留旋转空间，保持视频尺寸和宽高比不变。
- 「随视设置」（⌘,）集中管理平滑、反向、稳定锁定、旋转范围、画面大小和手动体验。
- 「暂停跟随」冻结当前角度；「回正」设为 0° 并暂停跟随。
- 人脸消失时保持当前角度，重新出现后平滑恢复。只跟踪画面中最大的人脸，适合单人使用。
- 摄像头在点击后才开启；手动模式会关闭摄像头。画面仅在本机处理，不上传、不保存，不请求麦克风或录屏权限。

摄像头权限被拒绝时，请在「系统设置 → 隐私与安全性 → 摄像头」允许随视使用。部分情况下需要重新打开应用。

## 观看预设与舒适控制（v0.6）

在「随视设置 → 头部跟随」选择预设，或使用菜单「观看」和全屏退出按钮的右键菜单切换。

- **定姿观看**：默认稳定 4 秒后锁定。自动解锁偏差改为相对锁定姿势超过 20°、持续约 0.45 秒；可调到 60°，也可选择「仅手动解锁」。只接受可信度足够的检测，单帧大偏差、低可信度、人脸丢失或长时间断帧不会解锁。输出尚未追上目标时不会提前锁在中途。
- **连续跟随**：默认关闭自动锁定和遮幕，跟随比例 65%，最大速度 30°/秒。各参数均可继续修改。
- **手动解锁 / 锁定**：⌘U 解除锁定或冻结，让画面从当前位置重新跟随；⌘K 锁定当前角度。关闭自动锁定的连续模式下，⌘K 会直接冻结画面。⇧⌘空格仍可冻结 / 恢复。
- **个人预设**：输入名称后「另存预设」，最多保存 20 个。保存当前跟随、补偿、遮幕、网格、运动点和背景 / 大小参数，支持切换和删除。切换内置预设保留当前背景和画面大小；切换时不重载视频、不启动摄像头、不突然跳转画面。摄像头、媒体、手动模式和校准姿势不会写入预设。

「补偿与遮幕」页提供以下设置：

- **大角度补偿**：默认启用，起点 15°，左右最大回收各 4°，通过渐入范围平滑增加补偿量；支持左右分别调整。先计算修正目标再转向，不会先转过头再回退。例如允许足够旋转范围时，60° 输入会得到 56° 的目标。补偿映射保持连续、单调，稳定锁定仍依据真实头部变化。
- **柔性遮幕**：定姿预设默认开启；确认新的姿势约 180ms 后，以 100ms 淡出视频和网格，80ms 暗幕内转向，再以 150ms 淡入。触发偏差、确认时间、各段时长及最短可见间隔均可调。暗幕内转向绕开普通慢速追赶限制，并同步内部跟随角度，避免淡入后被旧角度拉回。媒体和声音继续播放。跟踪丢失、暂停跟随或界面长时间挂起后恢复可见；连续不稳定的姿势不会反复遮幕。
- **实验性反向运动点**：默认关闭。根据几何限制后实际可见画面的角速度，平滑驱动边缘点反向移动；画面到达边界停止后，提示点减速停下。遮幕期间不把隐藏转向当作可见运动。可调强度、速度上限、数量、半径、不透明度，颜色沿用网格颜色。它不是车辆传感器功能，也未验证具有缓解眩晕的效果。

## 统一全屏观看

点击「全屏观看」或播放器全屏按钮进入统一的观看空间。原来的专注、透明模式已合并；「随视设置」分为「头部跟随」「画面与全屏」「背景与网格」「补偿与遮幕」「手动体验」，参数会保存到本机。全屏中按 ⌘, 打开设置，右键退出按钮也有设置、透明背景、引导线、冻结、居中和铺满选项。Esc 关闭全屏设置，再按 Esc 返回观看室。

### 大小、位置和旋转

全屏的大小与窗口内大小分别设置。全屏 100% 表示视频在零度时完整适配屏幕，默认 80%；转头过程中尺寸保持不变。

- **完整显示**：允许从 25% 放大到 100%，根据大小和位置计算可完整显示的连续旋转范围，在边界处停止继续旋转。画面放大或靠近屏幕边缘后，允许角度会减小；设置中显示当前约 ±多少度。100% 时通常没有继续旋转的空间。
- **自由旋转**：可继续放大，按设定的最大角度跟随，超出屏幕的部分被裁切。「铺满屏幕」会自动选择这一策略，并按视频和屏幕比例覆盖整个屏幕。
- **移动**：按住 ⌥ Option 拖动，⌥ 双击或 ⇧⌘0 居中。普通鼠标拖动仍留给进度条等播放器控件。完整模式内保持零度时的完整画面，移动后重新计算安全角度；自由模式允许画面部分移出屏幕，并保留可找回的区域。
- 窗口内保留原有固定尺寸与动态适配选项。B 站网页播放器仍使用固定的 960×540 视口，避免头部运动触发网页重新布局。

### 背景和引导线

「透明背景」位于背景设置顶部；开启后隐藏背景，视频仍然不透明，引导线可以独立显示。关闭透明背景后，可以选择 RGB 纯色或导入本地图片。背景不透明度支持 0–100%，图片另支持模糊和压暗，按屏幕比例居中裁切铺满。图片会复制到本机 Application Support 的 FromEyesToScreen/Backgrounds 目录，原文件移动后仍可使用，不上传到网络。

引导线统一为等距方格网格，删除其他形态选项。间距支持 24–180 点，越小越密；可调 RGB 颜色、粗细和不透明度。默认沿用现有的视频轴参照，随视频旋转、移动；关闭「网格随视频旋转」可改为屏幕固定参照。默认关闭网格，开启后默认仅显示在视频周围；满屏时若希望看到叠加网格，请关闭「仅在视频周围显示」。

默认开启「旋转时淡出网格」：检测实际画面转动后约 100ms 淡出，停止约 250ms 后约 150ms 淡入。未启用遮幕时也生效，可单独关闭；启用遮幕时会与遮幕共同控制可见性，恢复至用户配置的不透明度。背景始终固定在屏幕坐标中。

### 跟随与冻结

- 默认稳定 4 秒、容差 ±1.5° 后锁住当前角度。偏离锁定姿势超过 ±20° 且持续约 0.45 秒后恢复跟随（仅手动解锁时除外）；时间和容差可调。人脸丢失、长时间断帧不累计稳定时间。
- 跟随比例可调为 25–100%；例如 50% 时头转 20°，目标画面只转 10°。稳定锁定和解锁仍依据真实头部变化判断。
- 最大旋转速度可调为 5–120°/秒，默认 30°/秒，限制突然转头或重新识别人脸时的追赶速度。
- ⇧⌘空格冻结当前角度或恢复跟随；全屏右键菜单也提供此操作。手动体验不使用跟随比例，但会模拟速度限制、大角度补偿、遮幕和运动点，便于不开摄像头检查。

这些功能用于提供不同观看方式；舒适度需要实际体验比较，未验证能消除眩晕。摄像头和手动模式仍需用户主动开启。

## 哔哩哔哩视频（v0.2）

点击「打开 B 站视频」（⌘L），粘贴完整视频链接、BV / av 号，或带有 b23.tv 链接的分享文案，点击「打开视频」。支持 `p=2` 等分 P 参数，以及以秒计的 `t=90` 起播时间。短链接会先联网解析为完整视频地址。

v0.4 默认使用 [B 站主站视频页面](https://www.bilibili.com/)，通过原生 WKWebView 展示官方播放器。只调整网页呈现，隐藏播放器以外的内容；媒体选择、账号权限和清晰度仍由 B 站处理。观看区下方可以切换回 [官方外链播放器](https://player.bilibili.com/)，用于主站布局发生变化或加载失败时的备用播放。两种方式均不提取或下载媒体直链。使用播放器自身的播放、进度、清晰度、音量和弹幕控件；加载后必要时点击画面中的播放按钮。随视原来的本地视频进度条在 B 站模式下隐藏，避免显示错误的播放状态。

点击观看区下方「登录 B 站」，或菜单「播放 → 登录哔哩哔哩」，在随视的独立官网窗口中点击网页「登录」，自行扫码或输入账号。完成后点「完成并刷新播放」，再从主站播放器的清晰度菜单选择可用档位。登录窗口和播放器共享持久化 WebKit 网站数据，不读取其他浏览器的 Cookie，也不读取或记录密码。登录状态由网站处理并保存；高清、会员、地区或视频权限不会因嵌入而改变。登录页已验证可以到达，实际账号登录和登录后的高清播放需要用户完成验证。

- 旋转、平滑、校准、暂停跟随等与本地视频共用同一套逻辑。
- 使用观看区下方的「随视全屏」按钮保留旋转效果；网页自身的元素全屏关闭。
- 网页使用固定的 960×540 视口，通过外层缩放、旋转适配空间，避免每次头部运动都触发网页重新布局。
- 支持重新加载、在浏览器打开原视频，以及切换回本地视频。切换来源时暂停并卸载原网页，避免后台声音残留。
- 清晰度、登录要求、地域和视频可用性取决于平台。外链播放可能与主站不同，登录后优先使用主站播放。番剧、直播和收藏夹暂不支持。
- B 站模式需要联网，会向 B 站及其资源服务发出正常播放请求；摄像头画面仍然只在本机处理。嵌入网页的摄像头、麦克风访问请求会被拒绝。
- 网页登录状态使用随视自己的 WebKit 数据，不自动读取 Safari / Chrome 登录信息。登录由用户在平台页面自行完成；打开登录窗口会先暂停当前网页媒体。刷新登录状态或切换播放方式时尽量保留进度，网页加载后可能仍需点击播放。

## 本地开发

要求 macOS 14+、Swift 5.9+；本机使用 macOS 26.3.1 和 Swift 6.2.4 编译。
只需 Command Line Tools，不需要完整 Xcode，不依赖第三方库；构建、摄像头检测和本地视频不需要网络，B 站播放需要连接平台服务。

```sh
bash scripts/build.sh
bash scripts/test.sh
bash scripts/test-layout.sh
open build/随视.app
```

构建脚本生成 `.app`、应用图标和一段 10 秒的本地试播影片，并使用本机临时签名。此构建适合当前机器上的 demo，未做对外分发公证。更新源码后重新执行构建脚本；启动脚本只在应用不存在时自动构建。

构建同时在 `build/Symbols/` 保存与应用匹配的 dSYM，便于定位后续崩溃。

测试脚本检查角度计算、724 种旋转布局、平滑与角度限制、丢失人脸后的保持和恢复、校准、反向、微小抖动过滤及手动模式切换。采用独立 Swift 检查程序，兼容没有 XCTest 的 Command Line Tools 环境。

v0.3 增加稳定冻结、大小误识别、解锁、丢帧、缓慢转动、输出限幅前的解锁判定、可配置计时、不同采样率检查，以及 11,552 种固定尺寸旋转布局检查。构建缓存位于项目 `.build/`，图标直接由本机 Swift 代码生成与打包。

B 站链接检查覆盖 9 种合法输入、16 种无效输入，以及分 P、起播时间、分享文案、短链识别、去除分享跟踪参数和生成官方播放器地址。默认测试不依赖实时网络。

## 代码结构与后续扩展

- `Sources/MotionCore/HeadMotion.swift`：无 UI 的角度计算、姿势锁定、平滑与缩放几何。
- `Sources/MotionCore/ComfortMotion.swift`：补偿曲线、遮幕状态机、网格淡出和反向运动点速度滤波。
- `Sources/MediaCore/`：B 站链接识别、规范化和短链接解析。
- `Sources/EyesToScreen/CameraTracker.swift`：AVFoundation 摄像头输入和 Vision 人脸特征检测，后台串行处理、最多约 24 次/秒，丢弃积压帧。
- `Sources/EyesToScreen/AppModel.swift`：媒体导入、播放状态、校准和跟随控制。
- `Sources/EyesToScreen/PlayerViews.swift`：视频与摄像头的原生图层。
- `Sources/EyesToScreen/WebPlayer.swift`：官方网页播放器、网络状态、来源切换和网页权限边界。
- `Sources/EyesToScreen/BilibiliAccountWindow.swift`、`BilibiliWebConfiguration.swift`：独立官网登录窗口、共享网站数据和桌面 WebKit 兼容配置。
- `Sources/EyesToScreen/BilibiliPageLayout.swift`：主站播放器的呈现适配；网站结构改变时可退回外链播放。
- `Sources/EyesToScreen/BilibiliLinkSheet.swift`：链接输入和解析错误提示。
- `Sources/EyesToScreen/MainView.swift`：观看区和固定控制区。
- `Sources/EyesToScreen/AppSettings.swift`、`ViewingPresets.swift`、`SettingsView.swift`：参数、个人预设和统一设置面板。
- `Sources/EyesToScreen/ViewingWindowController.swift`：统一全屏窗口的生命周期、焦点和退出。
- `Sources/EyesToScreen/ViewingSurface.swift`：所有模式共用的视频布局，不随角度改变固定尺寸。

本地视频使用 AVPlayer，B 站使用 WKWebView，两种来源共用角度处理与观看区。后续可以在媒体输入层增加其他视频源，或为文档链接新增内容视图，继续复用跟随逻辑。网页嵌入权限、受保护的视频源及文档渲染需要分别处理。

支持的容器和编码取决于 macOS AVFoundation，推荐 H.264 / HEVC 的 MP4 或 MOV；不是所有 MKV、AVI 或带有特殊音视频编码的文件都能播放。摄像头方向、光线和侧脸会影响检测；极大侧倾超出本 demo 的目标范围。

### 播放时意外退出修复（v0.3.1）

用户提供的 v0.3.0 报告显示，主线程在 SwiftUI 测量原生视图的固有尺寸时触发 AppKit 布局断言。报告无法确定具体是哪一个原生画布。v0.3.1 为视频、摄像头、网页及窗口探测视图显式提供尺寸，避免调用约束引擎推算媒体画布大小；同时限制共享 WKWebView 只挂载到当前可见观看模式的容器，减少重复设置网页尺寸。

`scripts/test-layout.sh` 使用真实 NSWindow、NSHostingView、AVPlayer 和 WKWebView 运行本机回归检查：1,440 次连续角度变化、窗口尺寸变化、192 次观看模式切换和 6 次设置面板开关。网页使用含本地视频的测试文档，并检查切换后网页归属与文档状态保留。检查不开摄像头、不访问外网、不改用户设置；需先运行构建脚本生成试播素材。结果写入 `.build/checks/layout-regression-result.json`，本轮已通过。
