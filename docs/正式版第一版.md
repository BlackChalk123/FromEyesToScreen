# 随视 1.0 · 第一版

## 1.0.4 首次载入的网页小窗

- 修复 1.0.3 页面隔离调整后，B 站自动网页小窗与原生透明画布同时控制位置的问题。可重现的官网状态为 `data-screen="mini"`，播放器被偏移到视口外，只有点击网页小窗关闭按钮后恢复。
- 播放器的外围路径统一对齐固定网页视口，避免官网的粘滞布局沿用原页面的尺寸。发现网页小窗时，通过官方小窗关闭按钮退出该模式，不伪造播放器状态、不删除控件、不重载影片。
- 小窗尚未退出时不显示错误画面，也不报告播放器就绪。保留官方内部控件的显隐状态，以及 1.0.3 的旋转与摄像头会话行为。
- 官网检查新增首次进入时播放器左上角与视口对齐、宽高完整匹配的断言。仅验证点击到达页面不能发现此类显示回归。

## 1.0.3 旋转更新与播放器点击

- 摄像头测量改为受锁保护的单条最新值，由旋转时钟读取。主线程繁忙时覆盖旧测量，不再排队回放过时姿态；启停隔离继续使用会话代号。每次 Vision 分析使用独立自动释放池。
- `RotationEngine` 仍是唯一最终角度计算器。画面和井字线单独订阅角度，不再每帧通知整个应用、悬浮球和选片界面。打开控制面板后，角度文字最多每秒更新十次。未改变平滑参数、校准或角度映射。
- 官网隔离样式只隐藏播放器外的页面，不再强制显示播放器所有后代。修复隐藏的结束页 / 分享面板挡住视频主体点击的问题。找到播放器后停止整页变动监听，后续状态和容器替换由既有每秒检查处理。
- 跟随选择仅保存在本次运行内：首次启动默认关闭，主动开启一次后，返回选片会停摄像头，再进入观看时自动恢复。主动暂停后继续保持关闭，退出重启后也默认关闭。
- 新增实际鼠标事件的缩放 / 旋转坐标检查、隐藏面板隔离、跟随状态往返和新会话关闭检查。持续运行检查可用 `SUISHI_SOAK_SECONDS=120 bash scripts/test-v1.sh` 指定时长；`SUISHI_INSPECT_WEBSITE=1` 额外使用独立非持久网站数据检查公开 B 站页面，不读取正式账号。

此次针对可确认的更新与积压路径修复，没有清空网站缓存、登录或观看记录。真实摄像头下长时间观看的偶发卡顿仍需复测 T07 / T37；合成姿态和离线媒体不能证明所有真实场景都已解决。

两分钟合成姿态配合真实 WebKit 播放的检查记录：7,200 次角度更新，仅 26 次应用级通知，采样间隔没有超过 50ms。另有两小时算法回放通过。官网检查使用未登录的独立网站数据确认隐藏结束页不再挡住视频。

## 1.0.2 独立悬浮球与显示器尺寸

- 悬浮球拖动只改变球的位置，不再移动视频、不改变视频大小，也不会退出 100% 状态。球可单独放在另一块显示器上；切换视频显示器、改变视频大小或切换影片时不重新绑定球的位置。只有显示器断开导致球无法找回时才恢复到可见区域。
- 视频使用所选显示器对应的普通透明画布，不进入 macOS 独立全屏 Space。大小百分比统一以该显示器为基准，不再以此前较小的窗口为基准；透明区域仍可操作后方应用。
- **完整显示：100% 保持原始比例，完整适配所选显示器。** 宽高比不同时允许留边。
- **允许裁切：100% 保持原始比例，无边铺满所选显示器。** 超出的画面边缘裁切，不拉伸视频。
- `F` / 悬浮球的适配按钮在 100% 与之前的视频大小之间切换，不再切换两套尺寸基准。视频位置通过 Option 拖动调整，球内「视频显示器」菜单单独选择播放所在屏幕。
- 回归检查新增：实际双屏上 100% 尺寸、球跨屏独立拖动、拖球不改变 100% 视频、调整尺寸和切换视频屏幕不挪走球，以及超宽屏 / 竖屏的等比例完整适配和铺满计算。

本次通过 7,132 项核心与持久化检查、62 项原生集成断言，包含两块实际连接显示器上的独立拖球和 100% 尺寸验证。

## 1.0.1 修复与悬浮球

- 修复搜索页、UP 主空间等官网子域名点击视频后无响应：脚本消息校验允许 HTTPS 的官方 B 站子域名，仍拒绝非官方来源与非主框架消息。点击桥接不可用时保留原生导航后备路径。
- 选片窗口在系统全屏时，先等待退出其独立 Space，再显示透明观看窗口，避免观看窗口被留在不可见的 Space。
- 观看默认使用可移动的透明窗口，全屏铺屏改为可选。拖动悬浮球会连同观看窗口移动；球内「移到显示器」菜单可直接切换到任一连接的屏幕。切屏不重建播放器。
- 移除常驻顶部状态栏、底部工具栏和设置遮罩。全部随视控制集中到独立悬浮球：日常透明度 45%，指针移入或展开时用 220ms 平滑变为不透明。点击展开，关闭按钮或 Esc 收起；透明区域继续允许操作后方应用。
- 控制面板保留播放、刷新、返回选片、跟随、校准、井字线、画面大小和旋转参数。设置作为球旁的原生浮层，不再以整屏遮罩拦截操作。
- 新增首页、搜索页和空间页的严格来源桥接检查，验证脚本实际执行且在阻止原网页点击后仍能完成原生跳转。原生回归在当前连接的两块显示器上验证了窗口迁移、悬浮球、可选铺屏与返回窗口，并通过原有播放器生命周期检查。

当前通过 7,083 项核心与持久化检查、50 项原生集成断言；真实网站登录状态及更新前的观看记录在重启后保留。原有旋转算法未在这次修改中增加新功能。

构建产物是 `build/随视 1.0.app`，可以直接双击。旧的 `build/随视.app`、启动脚本和 Demo 源码保留，不与正式版共用偏好或账号数据。

要求 macOS 14+、Swift 5.9+。当前机器使用 Swift 6.2.4 / Command Line Tools 构建，不要求完整 Xcode，不引入第三方依赖。此产物采用本机临时签名，尚未做面向外部用户分发的签名与公证。

## 首版范围

1. 在 B 站官网浏览、登录、搜索，点开普通投稿视频自动进入随视透明观看；也可粘贴 BV / av、完整视频链接或 b23 分享链接。
2. 用户主动开启摄像头后，识别头部侧倾并旋转视频。保留基础平滑、校准和小幅角度微调。
3. 固定大小的画面、完整显示 / 允许裁切、Option 拖动、井字引导线与偏好保存。
4. 保存最近一个视频的链接、分 P、标题和可取得的播放位置；下次启动显示继续观看，不自动开启摄像头。

界面按 `prototypes/suishi-v1/index.html` 的黑白灰设计移植为原生界面。移除原型外框、评审工具、模拟照片、假推荐和假进度，选片区使用真实官网。引导线遵循用户明确要求，采用水平固定的井字形，仅在视频周围显示。

不包含旧版遮幕、自动锁定、补偿曲线、运动点、复杂预设、背景管理、本地视频或文档入口。未来内容扩展位置已经保留，不在首版提前实现。

## 操作

- 选片：官网点开视频，或在顶部输入地址并回车。登录直接在官网完成。
- 观看：普通透明画布与所选显示器对齐，不进入系统全屏 Space；视频默认显示为 60%。点击悬浮球打开控制，点开启头部跟随才请求摄像头。
- 暂停跟随：关闭摄像头并保持当前角度。返回选片也会关闭摄像头、暂停视频，但记住本次运行的跟随选择，再进入观看时恢复。每次重新启动软件默认关闭。
- 校准：将当前头部姿势作为水平参考，不自动把每次开启时的姿势当作零度。
- `⌘R` 校准，`⌘,` 设置，`G` 井字线，`F` 适配显示器（100%）/ 恢复之前的视频大小，空格播放 / 暂停。
- 拖动悬浮球只移动球，可独立跨屏停放。球内「视频显示器」菜单单独选择视频所在显示器；`⌥` 拖动调整视频位置，`⌥` 双击或 `⇧⌘0` 居中。
- `Esc` 先关闭设置，再返回选片；`⌘L` 返回选片。
- `⇧⌘R` 重新加载当前视频，通常仅在网页异常或平台状态改变时使用。

完整显示下，允许角度取决于画面大小和位置；100% 完整适配通常没有旋转空间。界面会显示安全范围和到达边界的原因。允许裁切时支持 ±75° 的目标范围，超出窗口的边角被裁切。极大侧脸、遮挡和双眼不可见时不保证检测，保留当前角度。

自动进入观看窗口与网页自动有声播放是两个行为。首次加载可能需要点击官方播放按钮。清晰度、会员、地域权限仍由 B 站决定，随视不提取媒体直链或绕过平台权限。番剧、直播和付费课程不属于首版支持范围。

## 架构与维护规则

```
HeadCamera → HeadSample → RotationEngine → 最终角度 → WatchView
                              ↑
                    ViewingLayout 的安全范围

官网选片 → AppCoordinator → BilibiliPage / 当前内容 → ViewingContent.surface
                    ↓
              RecentStore / Preferences
```

| 位置 | 责任 | 禁止混入 |
| --- | --- | --- |
| `Sources/RotationCore/` | 测量有效性、坐标、校准、单级平滑、角度边界和几何 | 网页、窗口、数据库、锁定和转场 |
| `HeadCamera.swift` | 后台采集、Vision 双眼识别、丢弃积压帧、过期回调隔离 | 画面布局、用户设置、上传或录像 |
| `BilibiliSession.swift` / `BilibiliScripts.swift` | 两个独立 WebView，共享网站数据；链接、弹窗、站内导航和官方播放器适配 | 头部角度计算 |
| `ViewingContent.swift` | 内容表面、元数据和重载边界 | 要求所有内容都实现视频播放接口 |
| `WatchView.swift` / `ViewingWindowController.swift` / `FloatingOrb.swift` | 单一透明观看容器、悬浮球、多显示器窗口移动、角度呈现 | 重建播放器或另算一套角度 |
| `AppCoordinator.swift` | 选片 / 观看流程、跟踪启停、保存时机 | SQL、网页 DOM 和运动算法实现 |
| `RecentStore.swift` | SQLite 和 schema 版本 | 摄像头、实时布局和网站凭据 |

`RotationEngine.angle` 是唯一最终角度。安全边界作为输入约束进入同一条管线，UI 不再对结果进行第二次限幅。丢失双眼、置信度不足或样本过期时保持角度，重新检测后从当前位置平滑跟随。默认保持 1:1 的角度映射，没有继承旧版补偿和跟随比例。

选片 WebView 与播放 WebView 各自固定在自己的容器中。观看窗口隐藏后仍保留原生容器；打开设置、调角度、返回选片或继续同一个视频均不搬动 WebView、不重载网页。登录交互会标记播放页需要刷新，下次进入时保留位置重载一次，以便重新读取平台登录状态。

网页使用 960 点宽的固定视口，视口高随媒体原始宽高比确定。头部运动只改变外层变换，不触发网页布局。官网结构适配集中在一个脚本文件，失败时显示恢复入口，不静默展示整页冒充播放器。

未来加入 PDF、普通网页或本地视频时，实现 `ViewingContent` 的内容表面和自身生命周期，在应用协调处接入。文档不需要实现播放 / 暂停；B 站专属 DOM 适配不应复用到普通网页。第二种来源接入前不建设通用插件系统。

## 本地数据

- 偏好：独立应用域 `local.fromeyestoscreen.suishi`，键 `viewing.v1`，系统 UserDefaults。
- 最近观看：`~/Library/Application Support/Suishi/Library.sqlite`，系统 SQLite，schema `user_version=1`，只保存一条最近记录。
- 写入：播放位置约每 5 秒合并保存，暂停、换片、返回选片和退出时补存；不逐帧写入。
- 网站登录：正式版自己的 WebKit 持久化网站数据。选片与播放共用；不读取 Safari / Chrome 登录状态，不把密码或 Cookie 写入观看记录。
- 数据库不可用时仍可播放，界面提示无法保存；遇到比当前程序更新的 schema 不覆盖原文件。

原计划使用 SwiftData，但本机 Command Line Tools 缺少 `SwiftDataMacros`。选择系统 SQLite 避免引入完整 Xcode 或额外依赖。SQL 仅在 `RecentStore` 内，后续存储替换不影响旋转或网页模块。

## 开发纪律

- 用户已确认的原型决定 UI，用户决定产品范围；实现过程中出现的新想法先记录，不顺手增加。
- 一次只调整一个旋转因素，区分测量、目标、显示边界；先用可回放角度序列定位，再做真实观看比较。
- 旧 Demo 保留为实验记录，新功能不得为兼容实验开关而扩张首版状态。
- 验收分别说明算法、原生窗口、真实网站和用户体验的验证范围；不以测试数量代替体验结论。
